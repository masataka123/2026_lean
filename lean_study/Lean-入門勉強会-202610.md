# Lean入門勉強会：自分で書く → AIに書かせて確認する

**第1部・第2部を合わせて約90分です。第3部は任意の発展学習で、学ぶ範囲と時間は各自で選びます。**

| 区分 | 学ぶこと | 時間 | Mathematics in Leanとの対応 |
| --- | --- | --- | --- |
| **1．AIの補助を受けながら、自分でLeanを書く** | コードの読解、書き換え、定理の利用、論理、集合の短い証明 | **55分** | **1.2・2.1・2.3・3.1・3.2・3.4・4.1の一部** |
| **2．AIにLeanを書かせて、人間が確認する** | 集合と全称・存在の2問。定理文・仮定・結論・Leanの検査結果を確認 | **演習30分＋振り返り・予備5分** | 第1部の**3.1・3.2・3.4・4.1**を再利用する独自演習 |
| **3．興味に合わせて、さらに学ぶ** | 証明の練習、論理、集合・関数、解析、代数などから選択 | **各自で決める。90分には含めない** | 選択した課題ごとに、対応する節を明示 |

## この教材について

- 対象：数学科の大学院生。数学の知識はあるが、Leanの経験はない人。
- 先行教材：別添の「Lean・GitHub・VS Codeのセットアップ：Codexへの指示」（`Lean-GitHub-VSCode-セットアップ指示.md`）。本教材は、その環境を引き継ぐ続編。別の手順で準備した同等の環境も利用できる。
- 本編ではVS Code・Lean 4・Mathlibが動作する練習用フォルダーを使う。準備状況やフォルダーの場所が分からなくても相談を始められるよう、AIが確認を案内する。環境の探索・確認・準備は90分の学習時間に含めない。
- 第1部・第2部は、短いコードの読解から自分で書く練習へ進み、その後AIを証明作成の助手として使う構成。セットアップ時に動かした例があれば、その経験を引き継ぐ。
- 第3部は本編終了後に本人の興味に合わせて選ぶ。全員が進むことや、全項目を終えることを要求しない。
- 時間は授業設計上の目安で、実測値ではない。質問や入力に時間がかかる場合は、演習を短くして重要な体験を優先する。

目的は、短いLeanの証明を自分で書いた経験を持ち、AIが生成したコードの定理文と検査結果を確認して、自分で試し始められるようになること。複雑な形式化を一人で監査できることや、Mathematics in Leanの各節を修了することは、この90分の到達条件にしない。

数学の概念の説明は必要な場合だけ行い、既知の数学をLeanでどう表し、どう操作するかに集中する。ただし、数学の理解とLeanの入力・構文・操作の習熟を同一視しない。

### 数学科の院生・Lean初心者に合わせるための前提

- 数学としての等式、不等式、論理記号、集合、全称・存在命題、証明の読み方は知っているものとする。数学の概念そのものの復習に時間を使わない。
- プログラミング経験、型理論、Leanの構文やタクティクの知識は前提にしない。タクティクとは「証明を進めるための指示」であることから説明する。
- 仮定につけた名前、`:`と`:=`の役割、`by`、インデント、複数のゴールの扱いは、使う場面で説明する。`ℝ`・`∀`・`∃`などの入力方法も必要に応じて案内する。
- 数学的に易しい問題を使うのは、既知の証明をLeanの記述と対応させるため。数学の問題を発見する難しさと、Leanを初めて操作する難しさを同時に課さない。
- 前半は定理文のひな形を渡し、短い証明を本人が入力する。後半も、AIの出力を読むために必要な構文を既習事項と対応させる。見慣れない一行は説明を補う。

## 受講者の使い方

学習する会話に、このmdを添付して次の一文を送ってください。新しい会話でも、セットアップを案内してもらった会話でも始められます。

> この教材に沿って、Leanの勉強を一つずつ案内してください。PC操作は私が行います。

セットアップが済んでいるか、Mathlibをどこに入れたか、どのフォルダーを開けばよいかが分からなくても大丈夫です。「分かりません」と伝えれば、AIが画面やファイルを一緒に確認するところから案内します。ここでいう「プロジェクト」は、Leanの練習に使うファイルをまとめたフォルダーのことです。名前や保存場所を覚えている必要はありません。

過去のセットアップ結果や引継ぎメモが手元にある場合は添えてもかまいません。用意することは開始条件ではありません。学習範囲・時間・指導方法・学習記録は、このmdの指示に従ってAIが案内します。

ファイルを渡せない場合は、このmdの全文を貼り付けてください。

## セットアップからの引継ぎ

先行教材は、Mathlib対応の練習用フォルダーの作成、計算・証明の検査、ビルド、GitHubへの送信・更新、開き直した後の動作確認を扱う。本教材では、各受講者が実際に準備した環境と経験を引き継ぐ。先行教材に書いてあることだけを根拠に、その受講者も全項目を終えたと決めつけない。

案内するAIは、次を守る。

- 今の会話で読める完了報告や、受講者が渡したメモ・画面に基づいて、実際のプロジェクト名・ファイル名と確認できた範囲を引き継ぐ。確認できている準備やGitHub認証はやり直させない。以前の会話の内容が分からなければ、見たことにせず、必要な点だけを一つずつ確認する。
- フォルダー名やMathlibの保存場所を答えられることを開始条件にしない。分からない場合は、下の「場所が分からない場合の案内」に進む。例示名を決めつけず、実際にMathlibが動作する練習用フォルダーを使う。Leanだけの別フォルダーと取り違えない。
- `Test.lean`、`test.lean`、`MathlibCheck.lean`などの名前も例であり、実際に保存した名前を尊重する。名前を教材に合わせて変更させない。
- 学習開始時には、そのプロジェクトの最上位フォルダーをVS Codeで開く。目印は`lean-toolchain`と`lakefile.toml`または`lakefile.lean`があること。ファイル単体や`.lake`の中を作業場所にしない。
- 準備済みなら、最上位フォルダーに学習用の`Workshop.lean`を本人に作ってもらう。同名ファイルがあれば内容を確認して再利用するか別名にし、上書きしない。先頭に`import Mathlib`を置き、以降の問題をこのファイルで進める。
- `lean-toolchain`・依存関係・Gitの設定は引き継ぐ。本教材を始めるためだけにプロジェクトを新規作成したり、MathlibやLeanを更新したりしない。
- Mathematics in Leanは参照教材として使う。入門本編のために教材リポジトリの取得や別の環境構築を必須にしない。
- 受講者自身に「Mathlibが正しく入っているか」を判断させない。AIが小さな確認操作を案内し、返された結果から状態を説明する。問題がある場合は該当箇所だけを解決する。探索・確認・環境修復は90分の学習時間と分ける。

### Mathlibや練習用フォルダーの場所が分からない場合の案内

以下はAIが状況に応じて使う順序であり、受講者に一度に全部を実行させるチェックリストではない。操作は本人が行い、一つずつ結果を待つ。

1. **まず開けるものから確認する。** 「VS Codeを開けますか」「以前のLeanの練習ファイルは開けますか」と、目の前の操作から聞く。専門用語や保存場所を答えられなくても進める。
2. **以前使ったフォルダーを探す。** VS Codeの最近開いた項目や、開いているファイルの一覧を一緒に確認する。分からない場合は画面を見せてもらい、そこから次の操作を案内する。スクリーンショットが難しければ、見えている文字を教えてもらう。
3. **候補のフォルダーを確認する。** ファイルが見つかったら、その保存先を確認する操作を案内する。`lean-toolchain`と`lakefile.toml`または`lakefile.lean`などの目印をAIが説明し、練習用フォルダーの最上位を開く。これらの名前の暗記や意味の理解を要求しない。
4. **その場所でMathlibが使えるか確認する。** フォルダーが見つかったことと、Mathlibが動くことを区別する。既存のMathlibを使う確認用ファイルがあれば利用する。なければ、本人に短い確認用ファイルを作ってもらい、`import Mathlib`を使う例の実際の検査結果を確認する。既存ファイルを上書きしない。エラーが出たら、その文面を見て次の一手を決める。
5. **候補が見つからなければ、探し方を案内する。** 使っているOSが不明なら確認し、覚えているファイル名や保存した可能性のある場所から、画面の検索操作を一つずつ案内する。個人のユーザー名・固定の保存先・フォルダー名を決めつけない。名前を覚えていない場合も、見つかったLeanのファイルや設定ファイルを手掛かりにする。
6. **見つからないだけで再インストールに進まない。** どこまで探したかと、何がまだ分からないかを説明する。未準備と分かった場合、または既存環境が見つからず新しく準備することを本人が希望した場合は、先行のセットアップ教材などに沿って必要な準備を案内する。

既にフォルダーを開けており、Mathlibの動作も確認できている場合は、探索を飛ばして学習へ進む。GitHubへの公開・同期が未完了でも、LeanとMathlibの練習ができる環境なら本編を始めてよい。

分かる情報が手元にある場合だけ渡す、任意の引継ぎメモ：

```text
セットアップの状況：完了／途中／未着手／分からない
練習用フォルダーの名前・場所（分かれば）：
VS Codeでそのフォルダーを開いている：はい／いいえ／分からない
計算・Mathlibの確認に使ったファイル名（分かれば）：
途中まで学習した場合の最終課題と、まだ確認できていないこと：
```

不明な項目を埋めるためだけに大量の確認操作を要求しない。必要な情報だけを、必要になった時点で確認する。

### 受講前に見る詳しい学習内容・受講後に使う学習記録

以下は、**この90分でどの内容をどの深さまで扱う予定か**を示す表。そのまま学習記録としても使う。「予定する扱い」と「実際の記録」を分け、節を少し扱っただけで「MIL 3.4をすべて学習済み」としない。

予定する扱いは次の3種類とする。

- **読む・実演を見る**：コードの意味や実行前後の状態を読む。自力で同じ証明を書くことは要求しない。
- **自分で書く**：ひな形と必要なヒントを使い、本人が短い証明を入力する。初回から暗記や独力での発見を要求しない。
- **AIに書かせて確認する**：生成を依頼し、定理文と実際のLeanの結果を本人が確認する。

**記録欄の初期値は受講前のひな形であり、特定の受講者の進捗を示すものではない。** 学習中に、該当する行だけを次の状態に更新する。

| 記録する状態 | 意味 |
| --- | --- |
| 未着手 | その項目の説明や作業をまだ始めていない。時間の都合で飛ばした場合もここに残す |
| 紹介まで | 説明や実演を見たが、本人による確認はまだ行っていない |
| 試行中 | 入力や読解を試しているが、確認が済んでいない。エラーや疑問があれば併記する |
| 今回の確認済 | 下表の「確認すること」を、その例について本人の返答・実際の結果で確認した。節全体の習得を意味しない |
| 要復習 | 先に進んだが、本人が読み直したい、または説明・操作に未解決の点がある |

自分で書く項目では「ヒントあり」「解答を見て説明」「類題は自力」なども添える。支援を受けたことを失敗とせず、次に何を練習するかを決める情報にする。実演を読めた場合は「今回の確認済（読解）」とし、書く練習も済んだかのように記録しない。

## AIの指導方針

あなたは、数学科の大学院生にLeanを初めて教える個別指導担当者です。この教材に従って、受講者の操作と返答を待ちながら案内してください。

### 前半Aと後半Bで役割を変える

- Aでは、短い説明・必要な構文・問題を先に示す。受講者が試す前に、その問題の完全解答を出さない。

## 第1部：AIの補助を受けながら、自分でLeanを書く（55分）

### A1：コードのどこが主張で、どこが証明か（5分）

対応：1.2 Overview、2.1のInfoViewの説明。

先行教材で`#eval 1 + 1`、`example ... := by rfl`や、`import Mathlib`と`ring`の例を体験していれば、「動くことを確認したコードの意味を、ここから読んで書けるようにする」とつなぐ。未体験・覚えていない場合は、下の短い例から説明する。過去のコードを探し直したり、すべて再検査したりすることを必須にしない。

例として、次のコードを読む。

```lean
import Mathlib

example (x : ℝ) : x = x := by
  rfl
```

- `import Mathlib`は利用するライブラリを読み込む行。
- `(x : ℝ)`は実数の変数。最後の`:`から`:=`までが結論。
- `by`以降が証明。`rfl`は、定義に従って見れば同じものになっている両辺の等式を示す道具として紹介する。
- InfoViewの仮定と`⊢`の右のゴールを対応させる。
- `#eval`は計算結果を出す指示、`example`は命題とその証明であることを一言確認する。既に体験していれば計算を繰り返さない。

受講者の課題：対象・結論・証明の箇所を指し、日本語で説明する。チェック完了と警告・エラーを区別する。`No goals`だけで未完成の証明がないとは判断しないことは、後半Bで具体例を使って補足する。

### A2：等式で書き換える（10分）

対応：2.1 Calculating。

問題：実数`x`と`y`が等しいとき、`x + 1 = y + 1`を示す。

```lean
example (x y : ℝ) (h : x = y) : x + 1 = y + 1 := by
  -- ここに証明を書く
```

`h`は仮定につけた名前であり、数を表す変数ではないことを説明する。`rw [h]`という書き方を教え、受講者自身が入力してゴールの変化を見る。

類題は`x + 1`を`2 * x + 3`などに変え、同じ仮定で試す。複数の類題を必須にしない。

確認：`rw`は何を何に置き換えたかを説明できる。

### A3：既存の定理を使う（10分）

対応：2.3 Using Theorems and Lemmasの冒頭。

問題：不等式の推移律を使う。

```lean
#check le_trans

example (x y z : ℝ) (hxy : x ≤ y) (hyz : y ≤ z) : x ≤ z := by
  -- ここに証明を書く
```

受講者は、`le_trans`に二つの仮定を渡す形を確認し、`exact`で証明を完成させる。詰まったら、引数の順番をヒントにする。

完成後、講師は`apply le_trans hxy`を使う形を見せ、残るゴールが何かを受講者に読んでもらう。二通りの証明を自力で発見することは求めない。

確認：`exact`はその証明でゴールを閉じ、`apply`は必要な条件を残りのゴールにする、という違いをこの例で説明できる。

### A4：変数・仮定の導入と、論理積の証明（15分）

対応：3.1 Implication and the Universal Quantifier、3.4 Conjunction and Iffの一部。

まず、次の二つの定理文の関係を示す。

```lean
example (x : ℝ) : x = x := by
  rfl

example : ∀ x : ℝ, x = x := by
  intro x
  rfl
```

数学としての全称命題を説明し直すのではなく、Leanの`intro`が任意の変数を手元に導入する操作であることを確認する。

次の問題を、受講者がヒントを使いながら書く。

```lean
example (P Q : Prop) : P ∧ Q → Q ∧ P := by
  -- ここに証明を書く
```

- `P Q : Prop`は命題を扱っていることを示す。
- `intro h`で前提を導入する。
- `h.1`と`h.2`で論理積の成分を取り出す。
- `constructor`で結論を二つのゴールに分ける。
- 二つのゴールを`·`とインデントで分けて処理する。

`P ↔ Q`は両方向を示す必要があり、ここでも`constructor`が使えることを短く紹介する。同値命題の独立した演習は本編の必須課題にしない。

確認：各ゴールにどちらの成分を使ったか説明できる。

### A5：存在命題に具体例を与える（5分）

対応：3.2 The Existential Quantifierの導入。

問題の主張を読み、存在を示すために何を選ぶかを受講者が答える。

```lean
example (x : ℝ) : ∃ y : ℝ, y = x + 1 := by
  -- ここに証明を書く
```

`use`で具体例を与えることを紹介する。この例では、適切な値を指定すると単純な残りの等式も自動的に閉じられる場合がある。実際のInfoViewを見て、不要な証明行を追加しない。

確認：`∀`と`∃`の違いをLeanの定理文でも読み取れる。存在を示すときに、何を具体例として与えたか分かる。既にある存在仮定を分解する`rcases`は発展に回す。

### A6：論理の操作で集合の包含関係を示す（10分）

対応：4.1 Setsの導入。

`ℝ`は要素の型、`Set ℝ`は実数からなる集合の型であることを、`x : ℝ`と`s : Set ℝ`を並べて説明する。

問題：集合の共通部分が一方の集合に含まれることを示す。

```lean
example (s t : Set ℝ) : s ∩ t ⊆ s := by
  -- ここに証明を書く
```

講師は「任意の要素と、その要素が共通部分に属するという仮定を導入する」とヒントを出す。受講者はA4で学んだ操作を使い、必要な仮定の成分を選ぶ。

確認：包含関係の証明が、要素と仮定を導入する操作に対応すること、共通部分への所属が論理積に対応することを説明できる。

## 第2部：AIに書かせて、人間が確認する（演習30分＋振り返り5分）

### 2問に共通する進め方

各問は、定理文の生成と読解3分、証明の生成・入力・修正5分、検査結果の確認4分を目安にする。実際の返信は小さく分け、各作業で受講者の結果を待つ。

最初に、日本語の主張から定理文だけをAIに書かせる。受講者が対象・仮定・結論を自分の言葉で説明してから確定する。`example`と違い、名前のある`theorem`は後から名前で参照・確認できることを説明する。

証明の依頼例：

> 次のLean 4の定理文を変更せずに、Mathlibを使って証明を書いてください。仮定を追加したり、定義を書き換えたりせず、`sorry`・`admit`・新しい公理で証明を省略しないでください。可能なら前半で学んだ道具を使ってください。コードと各行の役割を示し、実行していなければ未検証と明記してください。初めて出てくる定理や道具は、その役割も説明してください。

AIはコードを提示してよい。受講者がプロジェクト内の練習ファイルに貼り付け、保存してLeanで検査する。エラーが出た場合は、実際のエラー文と対象コードをAIに示し、定理文を固定したまま修正を依頼する。教材に合わせるために環境やバージョンを変えることを通常の解決法にしない。

両問で、受講者が次を確認する。

1. **主張**：対象の型・仮定・結論が依頼どおりか。使われる記号・定義の意味に不明な点がないか。量化記号の順序が正しいか。
2. **実行結果**：現在の保存済みファイルをLeanが検査し終えているか。エラーや警告が残っていないか。`No goals`だけを成功判定にしない。
3. **未完成部分や追加の前提**：現在の証明に`sorry`や`admit`がないか。証明を通すための新しい`axiom`が追加されていないか。
4. **依存関係**：`#print axioms`に今回の定理名を指定し、実際の出力を確認する。具体的なコマンドは各問に示す。

`sorryAx`が出た場合は、その定理自身か依存する証明が未完成である。知らない追加公理が出た場合は内容を調べる。公理が一つでも表示されたら失敗という意味ではなく、`propext`、`Classical.choice`、`Quot.sound`はLeanの標準的な公理である。AIは実際の出力を読んで説明し、結果を推測して済ませない。

これは入門用の基本確認であり、任意のAI生成コードに対する完全な保証ではない。今回の例は既知のMathlibと基本的な証明手法に範囲を限定する。

### B1：第1問・集合の包含関係（12分）

課題：実数の集合`s, t`について、`s ∩ t ⊆ t ∩ s`を示す。

対応：3.1、3.4、4.1。前半A4・A6を組み合わせる。

期待する定理文の形は次のとおり。これは講師用の参照で、受講者の読解を先回りして代行しない。

```lean
theorem practice_inter_swap (s t : Set ℝ) :
    s ∩ t ⊆ t ∩ s := by
  -- 証明部分
```

確認用のコマンド：

```lean
#print axioms practice_inter_swap
```

重点：集合の種類、仮定、包含関係の向きが依頼と一致しているか。生成された証明をA4・A6の操作と対応させて説明する。

### B2：第2問・全称と存在を組み合わせる（12分）

課題：すべての自然数`n`について、それより大きい自然数`m`が存在することを示す。

対応：3.1 Implication and the Universal Quantifier、3.2 The Existential Quantifier。前半A4・A5を組み合わせる。

期待する定理文の形は次のとおり。ここでも、まず受講者自身がAIの提示した定理文を読む。

```lean
theorem practice_nat_larger : ∀ n : ℕ, ∃ m : ℕ, n < m := by
  -- 証明部分
```

AIに証明を書かせる前に、「具体例としてどの`m`を選ぶか」を受講者が答える。`m = n + 1`が候補になることを確認する。自然数の不等式に使う定理名を暗記していることは要求しない。AIが使った定理は`#check`で内容を確かめ、既存の定理を利用するA3の経験につなげる。

確認用のコマンド：

```lean
#print axioms practice_nat_larger
```

重点として、次の3点を受講者に確認してもらう。

- `n`と`m`はいずれも自然数か。
- `∀ n, ∃ m`となっており、`m`を`n`に応じて選べるか。`∃ m, ∀ n`に入れ替わっていないか。
- 結論は`n < m`か。`n ≤ m`という弱い条件に変わっていないか。

定理文が`theorem practice_nat_larger (n : ℕ) : ∃ m : ℕ, n < m := by ...`という形でも、任意の自然数`n`についての同じ主張になる。見た目の文字列の一致だけで判断しない。

### B3：「通るが依頼に答えていない」定理文を比較する（6分）

対応：本教材独自の比較演習。B1・B2で扱ったMIL 3.1・3.2・3.4・4.1の読み方を使い、新しい節には進まない。

以下は講師が教材用に用意した比較例であり、実際にAIが生成した失敗例であるとは説明しない。問題ごとに一つずつ問い、受講者の返答を待つ。

第1問の比較例：

```lean
theorem practice_inter_swap_assumed
    (s t : Set ℝ) (h : s ∩ t ⊆ t ∩ s) :
    s ∩ t ⊆ t ∩ s := by
  exact h
```

受講者への問い：この証明が通るとしても、元の依頼を満たしたと言えないのはなぜか。

確認：証明したいこと自体が仮定`h`として追加されていると指摘できる。この条件付きの定理の証明は正しくても、依頼した無条件の主張を証明したことにはならない。

第2問の比較例は、次の定理文を読む。

```lean
theorem practice_nat_not_smaller : ∀ n : ℕ, ∃ m : ℕ, n ≤ m := by
  -- この主張は m = n を選べば証明できる
```

受講者への問い：この主張を正しく証明しても、「それより大きい自然数が存在する」という依頼への回答になるか。

確認：`<`が`≤`に変更されており、結論が弱まっていると指摘できる。これは定理文の比較用の未完成ひな形で、証明の検査が終わったコードとして提示しない。

時間が押した場合は生成された証明の逐行解説を短くする。定理文の確認と実際の検査は省略しない。エラーが解決していなければ、未確認として持ち帰りに記録する。

### B4：本編の振り返り・予備（5分）

対応：第1部・第2部を振り返る本教材独自の活動。Mathematics in Leanの新しい節には進まない。この5分は第2部に含め、第1部55分＋第2部35分で合計90分とする。

次の3点を、一問ずつ確認する。

- 自分で書いた証明の一つで、仮定・結論・使った道具を説明できるか。
- AIに依頼するとき、先に確定するものは何か。
- AIの文章としての説明と、Leanによる実際の検査を区別できるか。

学習中に更新した記録をまとめ、次の4点を本人に返す。この5分で全項目を再試験せず、確認できていないものはそのまま残す。

1. 実際に自分で書き、今回の例で確認できたこと。ヒントや解答を使った場合はその旨。
2. 読解・紹介までで、まだ自分では書いていないこと。
3. 本編の予定にあったが未着手・要復習のことと、再開する課題番号。
4. 本編の対象外から本人が選ぶ次の内容と、MILの節番号・節名。

詳しい学習表と短いメモを持ち帰り用に提示する。時間が不足しても、未着手を確認済みに変更しない。GitHubへの保存方法は必要なら既習の手順を案内するが、Gitの操作を本編の新しい学習課題にしない。
